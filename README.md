# 罕见病多中心登记数据受控分析与结果审查平台

六家医院协作的罕见病登记数据分析平台。各中心数据**不出院**：统计请求被编排到
中心本地代理执行，只有聚合统计量进入受控工作区；输出表经小样本抑制与结果审查
后才可发布，发布报告引用完整运行版本（规则版本、批次快照、审查决定、内容哈希）。

## 架构

```
┌────────────┐   ┌─────────────────────────────────────────────┐
│ React 前端  │──▶│ FastAPI 后端（编排运行 / 审查 / 发布）        │
└────────────┘   │  PostgreSQL：元数据、运行快照、审查记录        │
                 └───────┬─────────────────────────────────────┘
                         │ HTTP（仅下发规则+统计请求，仅回传聚合量）
        ┌────────┬───────┼────────┬────────┬────────┐
        ▼        ▼       ▼        ▼        ▼        ▼
     agent-C1 agent-C2 agent-C3 agent-C4 agent-C5 agent-C6   ← 中心本地执行模拟器
     （每个 agent 只读本中心 registry.csv；C2 结局用本地编码、
       C5 缺实验室指标字段、C6 为小样本中心）
```

- **数据管理员**：登记中心批次、变量字典与可用范围，锁定批次（锁定后不可变）。
- **研究者**：编辑队列规则（并发编辑走条件级三方合并）、提交统计请求、创建输出表。
- **结果审查员**：审批规则版本；对小样本/可差分推回的输出做合并、抑制或拒绝；
  批准后输出即发布，报告含完整溯源与哈希。

关键语义：

- 运行启动时**快照各中心已锁定批次**；运行中替换批次只影响新运行。
- 中心执行失败或缺变量映射 → 标记为**覆盖缺口**（`missing_mapping`/`failed`），
  不计为零例，总计只汇总成功中心并在结果中显式列出未纳入范围。
- 输出表任一单元格 `0 < n < k`（默认 k=5）或**唯一隐藏格可由合计差分推回**时，
  审查队列阻止放行，须合并分组、抑制单元格（必要时连合计一起抑制）或拒绝。
- 两名研究者并发改同一规则：后到保存收到 **409 + 条件级差异 + 自动合并建议**，
  确认合并后才能落库；已进入审核的排除条件不能被后一次保存静默抹掉。

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

- 前端：http://localhost:8080 （后端 API：http://localhost:8000）
- 首次启动自动：建库建表 → 生成六中心虚构数据 → 注册并锁定首批次 → 写入演示账号与一条已批准规则。

C2 批次更新演示（替换数据 → 登记新批次 → 新运行自动引用）：

```bash
docker compose run --rm datagen python -m center_agent.datagen --root /data --center C2 --seed 43
# 然后用 admin 登录 → 数据与批次 → C2「从中心同步」→「锁定」
```

预装运行时：Python 3.12（`/opt/python-3.12`）、Node 22（`/opt/node-22`）、
PostgreSQL 18（`127.0.0.1:5432`，库/用户/密码均为 `ccdev`）。

```bash
# 1) 依赖（首次）
/opt/python-3.12/bin/python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt -r center_agent/requirements.txt
cd frontend && npm install && cd ..

# 2) 生成虚构中心数据（首次）
PYTHONPATH=center_agent .venv/bin/python -m center_agent.datagen --root data/centers
```

前端开发模式 `npm run dev`（代理 /api 到 8000）；或 `npm run build` 后由后端直接托管。

## 跨中心检测口径校准

各中心把**同一生物标志物的原始结果**（如 `followup.lab_value`）按其本地检测口径
标准化后再进入协作组统计。单位虽然都是 mg/L，但检测平台、试剂批次、校准曲线、
参考区间、检出限与有效时期不同，**单位相同不等于同一测量尺度**——直接合并会把
实验室差异误读成患者差异。

- **登记**：每中心登记检测平台、试剂/批次、校准曲线、参考区间、检出限、有效时期
  与质控批次（`/api/harmonization/*`，数据管理员从中心同步）。
- **两条路线**：
  - 可溯源（traceable）：平台可追溯到同一标准物质，用在有效范围内的标准物质赋值
    拟合转换函数，只在校准覆盖区间内换算。
  - 桥接（bridge）：无共同标准物质，用一段时间的配对桥接样本估计平台间映射，
    并在留出样本上验证；要求配对样本覆盖 ≥2 个批次且质控通过。
- **不插补**：每个原始值在**中心本地**被分类为 `comparable` / `censored_low`
  （低于检出限）/ `below_range` / `above_range` / `qc_failed` / `outside_validity`
  / `uncalibrated`。只有 `comparable` 进入标准化均值；其余保留区间/删失状态并
  计入“无法比较比例”，绝不置零。
- **版本化**：每次拟合产生新校准版本并取代前一版本；运行启动时**快照**各中心
  使用的转换函数与哈希（`run_calibrations`）。**新校准只影响新运行**，历史运行
  保留当时的转换函数，可复现。
- **偏差诊断**：给出原始→标准化后的偏差收敛、留出 RMSE / 最大相对误差，以及
  按试剂批次的偏差**漂移**检测（漂移批次被标记为不可比或从拟合中排除）。
- 仅上报汇总覆盖/偏差/不可比比例，**不上传患者级检验记录**；拟合与诊断用去标识化
  参考/桥接样本值。标准化均值随「可比例数」一并受小样本 k 保护（可比例数极小或
  仅有 1 例时，均值可由单条记录还原，故与计数一样须审查）。

演示数据内建各验收样例：C1/C2/C4 可溯源且可比；C3 为双批次桥接（可比，且含一个
质控失败批次 C-2502）；C6 为单批次桥接（样本不足 → 不可比）；C5 无实验室字段且
无桥接样本（不可比）；C4 有效期中止（后续随访 `outside_validity`）。

## 验证方式（本题验收场景）

### 自动化验证（已实际执行）

```bash
.venv/bin/python -m pytest backend/tests -q     # 38 项单元/接口测试（含校准 21 项）
.venv/bin/python scripts/smoke.py               # 25 项端到端冒烟（需平台已启动）
```

冒烟覆盖：四角色登录、六中心锁定批次、全量运行、C5 缺字段→覆盖缺口而非零例、
校准覆盖与不可比中心、偏差诊断收敛、标准化运行的无法比较比例（含删失/超范围/
质控失败/有效期外，不插补）、运行快照记录校准版本与哈希、C2 重新拟合生成新版本且
历史运行保留当时转换函数、漂移批次诊断与排除、批次替换后旧运行快照不变/新运行用
新批次、运行对比、并发保存 409+条件级差异+确认合并、在审排除条件删除需确认、
小样本输出被拦截、合并+抑制后放行、发布报告溯源完整且哈希校验一致。

### 手工核对路径

1. **中心批次更新**：`admin` 登录 → 数据与批次 → C2「从中心同步」→「锁定」；
   旧运行详情批次快照不变，新运行 C2 引用新批次；运行对比页可见差异。
2. **并发改规则**：两个浏览器分别用 `researcher1`/`researcher2` 打开同一规则，
   先后保存 → 后者看到条件级差异弹窗 →「采用自动合并结果」→ 再保存；
   若合并结果删掉了在审排除条件，会再要求显式确认，且原在审版本保留。
3. **单中心缺字段**：新建运行勾选「实验室指标均值」→ 运行状态为
   「完成（有覆盖缺口）」，C5 标记 `missing_mapping`，总计 = 5 家中心之和。
4. **跨中心检测口径校准**：任一路径登录 → 顶部「检测口径校准」：
   - 校准覆盖表显示 C1/C2/C4/C3 可比、C5/C6 不可比及原因；
   - 点 C2「详情」查看留出验证指标、原始→标准化偏差、批次漂移表与去标识化样本；
   - 用 `admin` 点 C2「同步」→「重新拟合」（排除漂移批次 B-2502）生成 v2；
   - `researcher1` 新运行勾选「实验室指标标准化均值」，运行详情显示本次所用校准
     版本、可比范围、各分类计数与无法比较比例；对比页可见两次运行的校准版本差异，
     旧运行仍保留原转换函数（版本复现）。
5. **小样本输出**：用规则「RD03 且出生年 ≥ 2005」按 路径+性别 分组运行
   （C/F=4、C/M=2 小于 k=5）→ 提交输出表 → `reviewer` 审查：直接批准被拒 →
   合并 C 两组 → 抑制剩余小格 → 批准 → 已发布报告中可见完整溯源与哈希。

## 目录结构

```
backend/          FastAPI 后端（app/：模型、编排、隐私分析、校准拟合 calibration.py、
                  登记/拟合 harmonize.py、路由；tests/：pytest）
center_agent/     中心本地执行模拟器（datagen 虚构数据生成、assay 检测口径元数据、
                  executor 本地计算与本地标准化、server HTTP 封装）
frontend/         React + Vite（规则编辑、运行对比、审查、报告页面）
scripts/          dev.sh / stop.sh 本地启停、smoke.py 端到端验证
docker-compose.yml 一键部署（db + 6×agent + backend + frontend）
```
